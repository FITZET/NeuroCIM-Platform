## 三、目标架构

采用分层、可测试、GUI 与计算解耦的架构：

1. `domain`：数据模型、枚举、单位、错误模型 schema、线性度指标、实验配置和结果对象。
2. `data_io`：CSV/Excel 导入、编码和分隔符探测、列映射、预览、分块读取、缺失值策略、数据校验、结果导出。
3. `fitting`：包装 `1_data_fitting`，不复制算法；输出拟合参数、残差、R²、非线性误差、图表和可追溯 LUT。
4. `simulation`：单元乘法分支、阵列 MAC 分支、精确 LUT 算子、快速外推器、NeuroSim PPA 适配器。
5. `models`：统一模型/数据集注册协议，具体实现位于 `3_models`。
6. `training`：误差感知训练、QAT 对照、checkpoint、恢复、验证集选择和实验跟踪。
7. `application`：用例服务与后台任务队列，供 CLI 和 GUI 共用；GUI 不直接包含算法。
8. `gui`：Windows 桌面界面。优先采用 PySide6；若现有环境或打包验证表明不合适，可选择 PyQt5，但要记录许可和理由。
9. `infra`：配置记忆、结构化日志、资源清单、进程调用、导出和版本信息。

所有长任务在工作线程或独立进程运行，支持进度、取消、错误回传和结果恢复；禁止阻塞 GUI 主线程。外部输入错误使用用户可理解的提示，内部日志保留堆栈。

## 四、两条器件数据功能分支

### A. 单元乘法数据

支持 Virtuoso/TCAD CSV，包含输入映射、权重映射和输出电流/电压，允许用户配置列名、单位、编码、分隔符、文件编码及缺失值处理。兼容当前 256×256 网格格式，也支持长表格式。

实现并验证：

- 网格完整性、重复点、NaN/Inf、范围、单调性提示和单位校验；
- 1/2/4/8 bit；M、N 为正整数并覆盖 16、32、64；
- 电流域和时间域策略使用明确接口，不得以改标签代替算法；
- 复用现有 interaction 定义：
  `I(X,W)-I(X,0)-I(0,W)+I(0,0)`；
- 最小二乘拟合、非线性误差、RMSE/MAE、R²、最大误差，并保存拟合图和残差；
- 单元数据到阵列 MAC 的外推必须写清独立性、支路共享、累加和外围电路假设。

### B. 阵列 MAC 数据

新增真实实现，支持导入阵列规模、位宽、输入映射、权重或理想 MAC、输出电流/电压等列。允许 N 组、多文件和自定义映射。

实现：

- 按阵列规模、位宽、器件/实验组分组；
- 对理想 MAC 与测量输出做线性拟合和非线性建模；
- 输出 R²、INL/归一化非线性误差、RMSE/MAE、残差分布和置信区间（仅在数据支持时）；
- 建立统一的 `MacErrorModel`，可保存、加载、哈希校验和迁移 schema；
- 数据不足时拒绝不可靠外推并说明缺少的覆盖范围，不静默插值或生成随机误差。

两分支的中间格式必须有版本、输入来源哈希、单位、轴顺序、位宽、阵列规模、拟合方法、参数、适用范围、舍入/裁剪规则和创建环境。

## 五、神经网络、数据集和误差计算

建立注册式模型接口：模型声明任务类型、支持数据集、输入规格、预处理、checkpoint、量化策略、可映射算子、评价指标和资源许可证。新增模型只放在 `3_models/<model_name>/`，主平台通过注册表发现，不能在 GUI 中硬编码分支。

最终覆盖规格书要求的能力矩阵：

- 至少四种不同算力 DNN；其中必须包含 ResNet18 和 MobileNet 系列；现有 LeNet-5 可作为轻量基线；
- 一种真正的 BNN，权重/激活二值语义和硬件映射必须验证；
- 规格书资源条款中的 SNN 单独实现为脉冲网络任务，不得冒充普通 DNN；
- 一种可在普通 PC 有界运行的小型开源 LLM，用适合语言模型的指标；
- 至少四种主流数据集适配器，必须包含 MNIST、CIFAR-10 和 ImageNet 本地路径模式；第四种根据模型矩阵选择 CIFAR-100 或其他有明确许可证的数据集；语言模型使用独立文本数据集。

先完成可验收的阶段矩阵，再扩展全部组合。每个可用组合必须有真实 checkpoint 或明确训练命令、固定预处理、数据划分、资源哈希和许可证。没有资源时显示“未安装”，不得回退到随机权重。

精确器件推理继续使用真实四路径计算：

`X+W+ - X+W- - X-W+ + X-W-`

每次乘法经过所选 LUT 或 MAC 误差模型。不得用理想卷积后添加输出噪声替代。明确量化尺度、零码、padding、bias、累加精度、饱和和两支路共享假设。不支持的层必须报错或由经过验证的映射规则处理，不能静默回退为理想算子。

快速外推模式建立“线性度/误差特征 → 网络质量指标”的定量模型。训练数据必须来自真实精确推理实验或用户导入的标定结果，使用训练/验证/测试拆分和交叉验证，报告样本范围、误差、适用域和外推警告。不得只用“线性度越好准确率越高”的手写公式。缓存已验证的曲线后，快速外推应在 GUI 中满足交互响应需求。

## 六、误差感知训练

前向必须与最终精确器件推理一致；量化和查表使用 STE 或有依据的可微代理进行反向。文档明确精确前向、梯度近似和限制。保留浮点主权重，自动检查梯度有限、非零且参数实际更新。

支持：

- 从 checkpoint 微调、暂停、继续和取消；
- 固定随机种子及可配置 epoch、batch size、学习率和设备；
- train/validation/test 严格隔离；
- 最佳验证 checkpoint、最后 checkpoint、优化器和配置恢复；
- CPU smoke 和可选 GPU；
- 相同预算的普通微调或理想 QAT 对照；
- 训练曲线、逐层误差、混淆矩阵或任务相应指标。

不得降低误差强度、替换数据集、使用测试集调参或隐藏失败结果来宣称训练有效。

## 七、NeuroSim 内核

继续使用当前官方源码、构建脚本和薄适配层。NeuroSim 负责阵列映射和面积、延迟、能量、吞吐率等 PPA；本项目的 LUT/MAC 模型负责数值误差推理和训练。GUI 与报告必须准确展示这个边界，不能声称 NeuroSim 原生读取了测量 LUT。

每个支持模型应能：

1. 导出符合上游布局的权重和激活 trace；
2. 表达正负激活/权重的物理路径；
3. 配置位宽、subarray、parallel rows 和适用硬件参数；
4. 调用真实 C++ 可执行文件；
5. 解析总指标、逐层指标、stdout 和错误；
6. 保存命令、上游 commit、补丁、输入哈希和结果 JSON。

至少用两种网络完成真实 PPA 集成测试，不能把仅生成 CSV 算作 NeuroSim 执行成功。

## 八、GUI 功能

实现一个统一主窗口，按“导入 → 配置 → 计算/训练 → 查看/导出”组织，窗口可缩放并支持 Windows 高 DPI。至少包含：

1. 项目/运行管理：新建、打开、最近运行、运行状态和产物路径。
2. 数据导入：选择单元乘法或阵列 MAC；单文件/批量；编码、分隔符、列映射和缺失值策略；前 N 行、维度、类型和校验问题预览。
3. 阵列与位宽：M、N、1/2/4/8 bit、域类型、NeuroSim 参数；输入即时校验。
4. 线性度分析：一键后台计算，展示 R²、非线性误差、RMSE/MAE、拟合图和残差图。
5. 网络与数据集：按注册表过滤合法组合，展示模型/数据资源状态、checkpoint 和本地数据路径。
6. 推理评估：选择快速外推或精确模式，显示基线、理想量化、器件误差和差值。
7. 二次训练：参数配置、开始/暂停或取消、进度、日志、曲线、最佳 checkpoint 和复评。
8. NeuroSim PPA：配置硬件，运行真实内核，显示面积、延迟、能量、TOPS/W、FPS 和逐层表格。
9. 单样本实时推理：按索引/标签选择，显示输入、真实值、Top-k、置信度、耗时和关键量化/误差参数；语言与 SNN 使用任务相应视图。
10. 日志：查看、过滤、清空和导出 TXT；清空只影响展示或明确选择的日志文件。
11. 导出：CSV 和 XLSX，文件名包含时间、网络、数据集、误差模型和 run-id。

配置使用版本化 JSON 保存在用户配置目录，记忆最近阵列、位宽、网络、数据集和路径。禁止把用户机器绝对路径写死在源码。GUI 的每个核心按钮必须调用同一 application service，并有自动化测试或可重复的 GUI smoke 脚本。
